# COAP 方法说明

> 本文档仅描述 COAP（CACHE-OPTIMIZED ASYNCHRONOUS PLANNING）方法本身，
> 不涉及与其他方法的对比，也不涉及任何工程实现细节。

## 1. 方法目标

COAP 面向多智能体任务执行场景，目标是在保持动作可靠性的前提下，缩短
动作决策延迟。方法通过以下三条机制实现该目标：

1. **动作缓存**：把"前序动作 → 后继动作"的执行经验保存为可复用条目，
   使规划器在相似状态下可以直接基于缓存产生动作，而不必每次都进行完整
   推理；
2. **定时规划**：在当前动作执行期间按固定周期持续进行普通规划，让
   "下一个动作"在动作尚未结束时就开始准备，缩短动作之间的空档；
3. **双路竞速**：在需要产生新动作的时刻，让普通规划与缓存动作规划并行
   竞争，先得到可执行动作的一方胜出并立即执行。

## 2. 基本概念

### 2.1 动作

一个动作表示为：

```
u = <name, parameters>
```

其中 `name` 是动作标识（如移动、攻击、等待），`parameters` 是动作参数
字典。动作分为一次性动作（执行一次即完成）与持续性动作（启动后需要持续
轮询，可被中断）。

### 2.2 动作缓存条目

缓存保存动作转移经验，每条记录：

```
m = <A1, A2, score, reason, count, success>
```

- `A1`：前序动作；
- `A2`：后继动作，即在前序动作完成后执行的动作；
- `score`：缓存评分，衡量该转移的可靠性与优先级，取值 [0, 1]；
- `reason`：抽象化原因，描述在何种条件下由 `A1` 转移到 `A2`；
- `count` 与 `success`：累计尝试次数与成功次数，用于评分递推。

缓存条目可以来源于两种途径：

- **初始化生成**：任务开始时由模型根据任务目标与动作空间生成，未经环境
  验证，初始评分受限（见第 7 节）；
- **环境交互积累**：执行过程中由真实动作结果沉淀，可信度更高。

### 2.3 候选缓冲

普通规划结果与执行证据不会立即写入缓存，而是先以"候选记录"暂存：

```
d = <A1, A2, reasoning, status>
```

其中 `status` 取三种值：

- `success`：该转移对应的动作已在环境中成功执行；
- `failure`：该转移对应的动作被判定不可执行或执行失败；
- `uncertain`：该转移没有经过环境检验（例如双路竞速中落败一方的结果）。

候选记录按相同 `(A1, A2)` 分组聚合后，批量触发缓存内容更新。

## 3. 系统结构：四条并行线路

COAP 在同一任务运行内维护四条并行线路：

1. **动作执行线路**：取出规划结果并执行，轮询持续性动作状态，处理中断，
   产出结果反馈；
2. **普通规划线路**：以固定周期执行普通规划，为下一动作准备候选；
3. **缓存动作规划线路**：在双路竞速时，基于缓存检索结果快速产生动作；
4. **动作缓存管理线路**：负责缓存初始化、候选暂存、聚合、内容更新与
   评分更新。

四条线路并行运行，共享同一份任务记忆（观测、动作历史与通信记录）与
动作候选缓冲，彼此之间不存在全局同步屏障。

## 4. 定时规划机制

### 4.1 动作执行期间的定时规划

当前动作开始后，普通规划线路进入定时循环：每经过固定周期 `T` 触发一次
普通规划。规划结果写入动作候选缓冲，覆盖之前的候选。规划结果默认只作为
下一动作候选，不打断当前动作；当规划结果带有"立即中断"标记时，才会打断
当前持续性动作并立即执行。

### 4.2 动作结束时的处理

当前动作结束时，按以下三种情形处理：

**情形 A：动作结束前，定时规划已经完成（候选缓冲中已有结果）**

直接刷新定时器并采用候选缓冲中的结果作为下一动作，不进入双路竞速。

**情形 B：动作结束于下一次定时规划开始之前（候选缓冲为空）**

刷新定时器，并同时启动普通规划与缓存动作规划，进入双路竞速。

**情形 C：动作结束时，普通规划正在进行中**

不打断该普通规划，同时启动一次缓存动作规划，两条路径并行竞争。

### 4.3 计时器状态

```text
动作开始 ──► [规划计时中]
               │
               ├─ 到达周期 T ──► 触发普通规划
               │
动作结束 ──► 候选缓冲有结果？ ── 是 ──► 刷新计时，直接采用
               │
               └─ 否：普通规划进行中？ ── 是 ──► 不打断 + 启动缓存规划（竞速）
                                        └─ 否 ──► 刷新计时 + 双路启动（竞速）
```

## 5. 双路竞速

双路竞速中，普通规划与缓存动作规划共享同一个动作候选缓冲与同一个竞争锁：

- 两条路径各自完成动作生成与可执行性校验；
- 先通过校验并成功抢占竞争锁的一方写入候选缓冲，成为获胜者；
- 落败一方不丢弃结果，其动作转移以 `uncertain` 状态写入候选缓冲，作为
  潜在经验材料；
- 获胜动作被执行线路取走后，竞争锁释放，进入下一轮定时规划周期。

若双方都未能产出可执行动作（校验失败或超时），则将失败反馈注入上下文并
重新规划，重规划次数有限。

## 6. 动作缓存生命周期

### 6.1 初始化

任务开始时按配置选择初始化方式：

- **空缓存**：不生成任何条目，完全依赖执行过程积累；
- **模型生成**：由模型根据任务目标与动作空间生成初始转移条目；
- **复用旧缓存**：加载历史任务缓存，并按当前动作空间过滤无效条目。

### 6.2 候选暂存与聚合

执行线路在动作结束后，按以下转移关系生成候选记录：

- **上一轮刚结束的动作 → 下一轮被采用的动作**（常规转移）；
- **中断前的动作 → 中断动作**（当定时规划打断当前持续性动作时）。

缓存管理线路按固定条件触发批量提取：候选缓冲中记录数达到阈值，或距上次
提取的时间达到阈值，任一满足即执行一次"聚合 → 内容更新 → 评分更新"。

### 6.3 内容更新

对每个聚合后的 `(A1, A2)` 分组：

- 若该转移已存在于缓存中，使用分组内的原因集合更新该条目的抽象原因；
- 若该转移不存在，则创建新条目；有环境证据（成功/失败计数）时使用证据
  成功率作为初始评分，无环境证据时初始评分受限。

### 6.4 检索

给定上一动作，缓存管理线路检索所有前序动作匹配的条目，按评分降序返回
前 `k` 条，作为缓存动作规划的候选输入。**前序动作只按动作名匹配，忽略
参数**，使不同参数下的同类转移（如 `f(a1)→F(a1)` 与 `f(b1)→F(b1)`）共享
同一规律；参数级差异由双路一致性（重要参数对比）负责判定，不参与检索。

## 7. 评分更新

每条缓存条目维护周期增量计数（本周期内新增的尝试数、成功数与命中数）。

**初始评分约束**：模型初始化生成的条目未经环境验证，初始评分限定在
(0, 0.5]；只有后续执行成功被强化后，评分才可能超过 0.5。

**实时递推**：评分更新不调用模型，只要存在任一待处理反馈即由缓存维护
线路触发更新（轮询粒度约 1 秒），从上一轮评分递推：

```text
Δc = 本周期新增尝试数
Δq = 本周期新增成功数
r  = Δq / (Δc + ε)                    # 周期成功率，ε 为极小正数防除零

# 方式一：置信度调整 + 指数平滑（默认）
α  = λ / (λ + 累计尝试数)              # 经验越多越信任反馈
score = (1 - α) × score + α × r

# 方式二：增量奖励-惩罚（单次反馈在线更新）
score = score + α × (y - score)       # y ∈ {0,1}，成功为 1，失败为 0

# 方式三：频率感知（本周期无尝试时的空闲衰减，可选）
score = score × (1 - 衰减率)

score = clip(score, 0, 1)             # 始终保持在 [0, 1]
```

评分更新不调用模型，仅依赖执行统计。

## 8. 重要参数对比

双路规划产生的动作可能并不完全一致。一致性判定规则为：两个动作等价，当且
仅当动作名称一致，且所有被标记为"重要"的参数一致。非重要参数的差异不
影响一致性判定。

该判定用于：

- 双路竞速中判断普通规划动作与缓存动作是否一致；
- 决定候选记录的状态（与已成功动作完全一致才记 `success`，否则记为
  `uncertain`）；
- 决定缓存强化条件（缓存动作执行成功，且与普通规划动作在重要参数上一致
  时，才对该缓存的成功计数进行强化）。

## 9. 流式输出

规划调用采用流式输出，并要求模型按固定顺序生成内容：

1. 先输出动作段（JSON 对象，包含动作名、参数以及普通规划所需的立即中断
   标记）；
2. 再输出一个固定的就绪标记；
3. 标记之后可选择输出通信段（JSON 对象，包含消息文本）。

框架一旦从流式输出中解析出完整的动作段，即可立即进行可执行性校验，无需
等待通信段生成完毕。动作可执行则其通信段有效；动作不可执行则通信段作废。
双路竞速时，先完成动作段解析且通过校验的一方获胜。

## 10. 通信机制

方法包含两类通信：

- **主动通信**：随规划输出产生，由模型生成消息文本，在对应动作成功执行
  后提交并广播；
- **被动通信**：动作结束后自动生成紧凑的结果反馈文本（说明动作完成、
  中断或失败及原因），不经过模型，直接广播并记录到通信历史。

通信历史按用途区分记录：主动通信与被动反馈写入不同类别，供其他智能体
读取；其中动作结果反馈不注入规划输入中的"团队消息"部分，避免信息噪声。

## 11. 记忆

每个智能体维护一份任务记忆，包含：

- **观测**：持续更新的环境观测文本；
- **动作历史**：已规划与已执行动作、参数、状态与结果；
- **通信记录**：主动通信与被动反馈消息，按类别区分。

规划输入由记忆内容组织而成：身份信息、最新观测、团队消息、当前动作与
结果、动作空间与任务目标，以及缓存路径所需的候选缓存列表。

## 12. 输出协议

方法的模型输出协议如下：

| 用途 | 协议 |
| --- | --- |
| 普通规划 | `{"reasoning","action","interrupt"}` + 就绪标记 + `{"communication"}` |
| 缓存动作规划 | `{"action"}` + 就绪标记 + `{"communication"}` |
| 缓存初始化 | `{"entries":[{index,previous_action,next_action,reason,initial_score}]}` |
| 缓存内容更新 | `{"reason","initial_score"}` |

其中：

- `reasoning`：普通规划的显式推理文本；
- `action`：动作对象（动作名 + 参数字典）；
- `interrupt`：布尔值，仅普通规划输出，表示是否应立即中断当前动作；
- `communication`：可选的主动通信消息；
- 缓存初始化的 `initial_score` 限定在 (0, 0.5]。

## 13. 决策流程总览

```text
动作执行中：每周期 T 触发普通规划 → 结果入候选缓冲
动作结束：
  候选缓冲有结果 → 直接采用，刷新计时
  否则 → 双路竞速（普通规划 + 缓存动作规划，先得先执行）
执行线路：取候选 → 校验 → 执行 → 结果反馈（成功/失败/中断）
   ├─ 生成候选记录（常规转移 / 中断转移）
   ├─ 成功后提交主动通信
   └─ 广播被动反馈
缓存管理线路：阈值触发 → 聚合 → 内容更新 → 评分更新
```
